## Implementation details

- Explicit InternalModuleAccess registry drives 0/1/>1 landing, default-deny classification and effective permission gates. Pegawai is not a deny rule.
- InternalIntendedUrl validates same origin, registered GET route, module, page/resource and record authorization. Login consumes intended once and uses generated fallback destinations.
- InternalModuleNavigation uses supported Livewire current component mapping and registered HTTP route context. No active_module session, Referer, tenancy or global component-payload heuristic. Existing groups are scoped to the current workspace.
- Persistent module middleware retains SDM/PAK boundaries on HTTP and Livewire. Active-account middleware priority runs before authentication to preserve logout of inactive accounts.
- Super Admin receives all registered web pak.* explicitly and idempotently. Other roles and existing account assignment/status/person mapping are not altered by this correction.
- PAK granular policies/services and published DUK read-only whitelist are preserved. Verified histories, master JF, PakRuleSet first_used_at immutability, PakCase/snapshot/audit are untouched.

## Technical adaptations

The installed Livewire update route is generated through Livewire::getUpdateUri(). A real HTTP refresh sends an empty calls list, matching client refresh behavior; $refresh is a test helper/client action rather than a callable PHP method. Laravel middleware priority required explicit positioning of the existing active-account middleware. LoginResponse uses the active session store because Livewire's response request is not guaranteed to carry a request-bound session. These are framework integration adjustments, not business/schema changes.
